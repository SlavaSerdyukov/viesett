# Private document handling and sensitive-content policy

Files are processed only to analyse the selected property and build its buyer dossier. There is no mailbox ingestion, correspondence archive or automatic third-party communication. Users see layered upload guidance and acknowledge the current version of their entitlement to supply documents. This is separate from Privacy Notice acknowledgement and third-party consent.

Accept raw PDF bodies only. Validate actual streamed request size before parsing and enforce file size before storage. Validate declared type, PDF signature and EOF marker; these establish a conservative file-type baseline, not complete structural validation. Sanitize display metadata, compute SHA-256, use a server-generated 64-hex key, run the malware scanner, then the sensitive-document gate. No user filesystem path is stored or used. Same-workspace duplicates return existing metadata with HTTP 200; first upload returns 201. Cross-workspace/user uploads get independent IDs and objects.

The explicit lifecycle is `UPLOADED → SCANNING → READY | QUARANTINED | REJECTED`, followed by deletion. Failed/unavailable/timed-out scanning quarantines, never readies. `UNKNOWN` is a valid classification independent of safety. Rejected bytes are immediately removed, metadata remains available for review/deletion. Quarantined bytes remain private, cannot be downloaded normally and cannot feed evidence or AI. There is no release-quarantine endpoint. A future reviewed rescan workflow must preserve these invariants.

Sensitive content includes identity/eID/passports and National Register numbers; health, political/religious beliefs, sexual orientation, biometric/genetic information; unrelated bank records; and unrelated private correspondence. Clearly identified material is quarantined. The bundled sensitive gate checks clear filename/byte markers and misses some embedded text/images/compression. The bundled development scanner is a deterministic double, not a malware defence. Default scanning is unavailable/fail-closed; development opt-in is explicit; production startup refuses unreviewed adapters. Add reviewed sandboxed parsing/scanning before public document processing. No parser/OCR is supplied now.

Local object directories are 0700 and files 0600. Writes use exclusive creation and reject final-component symlinks. Reads reject symlinks and validate keys. Operate a service-owned, trusted storage directory; protect parent directories against untrusted writers. Opaque keys never leave the service. No static mount or public object URLs exist. Authenticated ready-document downloads reauthorize every request and use UUID attachment names, no-store and nosniff headers. Deployment must add disk/backup encryption and least-privilege service access.

Upload writes have a durable ten-minute cleanup reservation before bytes are created; database success removes it. Request time is bounded below the reservation lease. Crashes leave cleanup tasks. Deletion atomically removes accessible metadata/dependencies and queues opaque object keys; it attempts physical removal immediately. Storage failures return 503 pending deletion, leave content inaccessible and retain a retryable task. Run `viesett purge` regularly and monitor failures/task age. Reservation and cleanup records disappear after successful object deletion. Source-linked findings/evidence and generated request drafts are removed or invalidated. No dossier retention exemption is fabricated.

No raw bytes, extracted text, filenames, tokens, request headers, SQL parameters or provider exception representations belong in ordinary logs/traces. The application emits only structured allowlisted correlation/method/status events and disables verbose validation responses. Keep Uvicorn access logs, SQL echo, request-body capture and external APM content capture disabled. Test doubles intentionally raise content-bearing errors to verify that logs/responses remain clean.

Archive purge is configurable and off by default. Active dossiers remain until deleted. Security-log sink retention is a separate operational decision; there is no content-bearing audit table or indefinite default log archive. Before hosted use, approve backup expiry, restore/deletion replay, processor deletion, antivirus/sensitive detection, encryption, scheduling, quotas and per-tenant abuse monitoring. No production safety guarantee is inferred from a development green test suite.
