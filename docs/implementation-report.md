# Viesett Milestone 1 implementation report

Historical foundation report. Current changes: [Milestone 2 report](implementation-report-m2.md).

Prepared 2026-11-11. Local backend foundation; not a public production service. Verification results and exact commands: [verification](verification.md).

1. **Directory/repository:** standalone `./viesett`, its own Git repository, human name Viesett and Python/project slug `viesett`. Source, tests, migration, Docker/Compose, lockfile, workflow and documentation are here. No existing application source or configuration was edited.
2. **Architecture:** modular monolith with versioned FastAPI, Pydantic v2, async SQLAlchemy 2 and authoritative PostgreSQL. Narrow storage/scanning/interpretation interfaces; no generic repository framework, microservices or Redis. [Architecture](architecture.md).
3. **Data model:** Account, ApiToken, PropertyWorkspace, PropertyDocument, EvidenceItem, Finding, FindingEvidence, DocumentRequestDraft, PolicyVersion, UserPolicyAcknowledgement, Processor and ObjectDeletionTask. Random UUIDs, domain enums, constrained typed payloads and composite workspace foreign keys. No identity-document kind or mailbox model.
4. **Authentication/ownership:** opaque random expiring bearer tokens, SHA-256 digest-only persistence, no profile PII required. CLI-only development account provisioning; production provisioning disabled. Router authentication, owner/workspace query filters and uniform 404 for absent/foreign records. No social login, recovery or public onboarding.
5. **Private storage:** provider-neutral interface and filesystem implementation, opaque 64-hex keys, 0700/0600 permissions, exclusive writes, symlink/key validation, authenticated per-request downloads. No public URL or storage key in response/export. Filesystem parent directories must be trusted.
6. **Document safety:** streamed request/file bounds, PDF declared/actual type baseline, sanitized filename, SHA-256, malware scanner, sensitive-content gate and explicit lifecycle. Scanner errors/timeouts quarantine. Rejected bytes are deleted; quarantine cannot reach downloads/evidence/AI. PDFs only. Default scanning fails closed; explicit development doubles and reviewed production adapter gate.
7. **Evidence/findings:** append-only typed evidence with source locators and OFFICIAL/DOCUMENTED/INFERRED authority. Finding provenance and same-workspace references are first-class. Source removal deletes dependent evidence/findings. BLOCKING_DATA_GAP means insufficient reliable evidence, not a legally prohibited purchase. No full rule engine is supplied.
8. **AI boundary:** optional provider-neutral interpretation of at most three explicitly selected ready-document sections, totalling 8000 characters. Disabled without provider/processor. Typed proposals map only to new INFERRED rows; no authoritative overwrite API. No commercial SDK, credentials, live call, whole-archive forwarding or training implementation.
9. **Privacy/legal bases:** five required privacy drafts plus product/security documentation. Purpose-specific candidate bases and necessity, versioned notice/Terms/upload records; no blanket GDPR-consent or marketing field. Processor defaults disable training, DB constraint forbids it, production/runtime checks require review. [Matrix](privacy/legal-basis-matrix.md), [ROPA](privacy/ropa.md), [DPIA](privacy/dpia-draft.md).
10. **Third-party data:** buyer attestation is not consent from named people. Minimise identity copying and preserve property-source provenance. Article 14, information obligations and operator rights/restriction handling are explicitly open for counsel. No automatic third-party contact. [Third-party handling](privacy/third-party-data.md).
11. **Deletion/export:** individual source, workspace and account deletion; cascade metadata/dependencies; token revocation on account deletion. Durable cleanup reservations/outbox allow idempotent physical erasure after crashes/storage failures. API hides removed data immediately and reports pending cleanup honestly. Export is caller-only metadata with policy versions and source references; ready binaries use separate authenticated download. Archive purge configurable/off by default; security-log retention separate.
12. **Generated request text:** deterministic English/Dutch templates, stable ordering and duplicate-kind normalization; persisted plain text without recipients, mailbox credentials or delivery state. User copies and sends in their own channel. No backend send operation.
13. **Tests/coverage:** 78 tests passed with 91.85% branch-aware combined coverage. Real PostgreSQL integration tests and deterministic local safety/AI doubles exercise isolation/enumeration, content/size/path rejection, logging, duplicate scope/concurrency, quarantine, evidence authority, processor review/training prohibition, acknowledgements, exports, physical deletion, retry/purge and archive races. Exact results are in [verification](verification.md); the 85% threshold is enforced.
14. **Hosted CI:** GitHub Actions workflow contains frozen uv sync, Ruff lint/format, strict mypy, clean PostgreSQL migration/drift check and pytest coverage gates. No Git remote was provided/configured, so no hosted run or hosted-green status is claimed. Publishing to GitHub is outside this local creation task.
15. **Migrations:** frozen explicit initial Alembic migration `5e1e917449ce`, including versioned draft policies. Empty-database upgrade, downgrade/re-upgrade and schema drift are checked locally. PostgreSQL 16 is configured in CI and Compose; local verification uses installed PostgreSQL 15.15. No runtime `create_all`.
16. **Counsel questions:** controller/contact/roles; final bases and balancing; third-party Article 14 procedure; incidental sensitive identifiers; notice/Terms; rights/restriction/redaction process; actual processors and transfer safeguards; dossier/backup/security-log criteria; DPIA threshold/residual risk; incident duties. No Belgian legal approval or final compliance conclusion is claimed.
17. **Intentional limitations:** no public registry/source integrations, OCR, full PDF parser, production antivirus/sensitive detection, live AI, rule engine, UI, mailbox, brokerage, mortgage or binding workflow. Production startup deliberately blocks until reviewed safety adapters are injected. In-memory rate limiting supports one worker; shared limits, hardened hosting, encryption/backups, rights operations and final authentication are deployment milestones. Docker build/hosted execution are reported only if actually verified. This is not public-beta authorization.
18. **Next milestone:** Flemish property resolver and approved official/public data enrichment, with source locators and legal/technical review. Document intelligence/deterministic rules follow in Milestone 3; cross-document dossier UX follows in Milestone 4.
