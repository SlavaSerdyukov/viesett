# Conditional information and buyer context

The document checklist now separates **Required now**, **May apply** and **Received**, with not-required/not-yet-applicable items in a separate disclosure. Conditional unknowns do not count as confirmed missing requirements or enter the completeness denominator. The same grouping is used in the notary print view. Concise explanations precede technical check details; users do not see RuleContext fields as a questionnaire.

The only supported buyer context need is `KNOWN_DEED_DATE`: the date of an already signed authentic deed. It appears only for usable, consistently labeled EPC E/F residential information when trusted qualifying-transfer and exemption/inherited-obligation conditions are already established and no usable trusted date exists. Conflicting labels/dates, expired/unusable EPC information or missing prerequisites do not prompt the buyer. Property address, parcels and certificate facts are fetched/extracted instead of asked again. The date question is optional; other dossier work continues without an answer.

`MissingContextQuestion` exposes code, question, why, DATE answer type, affected rule code and source preference. A supplied date creates MANUAL / **UNVERIFIED** evidence with input-policy `user-transaction-context:1.0.0`, bound to the current property identity revision. It does not become OFFICIAL or DOCUMENTED and cannot override source information. Future/invalid dates and unexpected fields are rejected; repeated identical answers reuse the current observation. Removal supersedes the answer, preserving explicit history/export until source/workspace/account deletion.

Existing regulatory predicates reject unverified facts by default. Only the existing EPC renovation timeline explicitly accepts the allowlisted date for a visibly qualified **provisional** date, after all its other conditions are satisfied. It does not satisfy a document requirement or determine legal debt/payment responsibility. Electrical deadlines and unrelated rules ignore it. Trusted official/matched documentary data takes precedence; source conflicts remain unresolved. Tests compare unrelated conclusions, sources and requirements before/after an answer.

No Belgian rule, statutory period or applicability exemption was added. The reviewed M3 catalog remains 1.0.0; the separately versioned change is input-authority handling and explanatory presentation. Evaluation hashes include the new authority/input policy so old snapshots remain immutable and new results recompute. Current dossier citations are sorted to avoid source-order jumps on refresh. User-provided context remains visible separately in Evidence and the print handoff.

Completeness is information availability, not safety. A missing-data finding is not a legally blocked sale. A proportional works estimate is not legal debt. These distinctions appear next to counts, gaps and estimates rather than only in a footer. Source unavailable, invalid response, not found, partial relations and stale retained results remain distinct. A failed refresh can show the last cached dossier with an explicit message.
