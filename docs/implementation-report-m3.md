1. **Areas changed:** new document-intelligence/domain/persistence/rules/services/API modules; existing evidence locators/types, finding provenance, export/deletion, readiness/config, additive migration, CI, fixtures/tests and focused technical/privacy docs. Existing authentication, document safety and official-source resolver architecture remain.
2. **README:** no M3 edit. Exact entry SHA retained, including preexisting uncommitted M2 text. No exceptional rewrite was needed.
3. **Migration:** `192e0442ffc8` after unchanged `da321bc669fb` and `5e1e917449ce`. Adds DocumentAnalysis, DocumentTextArtifact, DueDiligenceEvaluation, source/analysis compound foreign keys, bounds, extractor provenance constraint and notice `2026-11-12-m3`. Old policy text/acknowledgements and upload policy stay preserved. Downgrade is guarded when M3 dossier state exists.
4. **Text extraction:** pypdf in a disposable Python process, fixed module/no shell, explicit page/character/stream/input/time/CPU/memory limits. Conservative normalization and one-based separate pages. No content/exception diagnostics in logs.
5. **Derived lifecycle:** complete text is a private page-JSON object; relational metadata records hash/parser/pages/key only. Key is durably associated before writing, covering partial writes/crashes. Existing outbox handles cleanup failures; source/workspace/account deletion queues successful/reserved derived objects and removes analysis/evaluation dependencies. No storage key is exported.
6. **OCR_REQUIRED:** insufficient or mixed text layers remain explicitly unsupported/OCR_REQUIRED, without empty-success evidence. No OCR SaaS/binary/credentials are needed. Encrypted/malformed/limit failures remain separate typed failures; safety status is preserved.
7. **Classifier:** `signals:1.0.0`, heading 0.6 + issuer 0.2 + vocabulary 0.2; >=0.8, two signals, exactly one family heading. Weak/mixed packets UNKNOWN. No filename inference or AI.
8. **Manual classification:** authenticated workspace-scoped `manual_kind` on analyze; new generation, original automated prediction retained, correction explicitly recorded, selected adapter re-extracted, earlier evidence expired/linked. Unchanged retries are idempotent.
9. **Association:** exact normalized street/house/postal/box or source CaPaKey comparison. Missing unit precision remains POSSIBLE_MATCH, conflicts MISMATCH, absent/currently stale official identity UNVERIFIED. Uncertain/unrelated document evidence is retained for review but excluded from substantive property rules. Refresh re-associates against current M2 identity.
10. **EPC fields:** reference, labeled address/box, issue/printed expiry, typed A+–F label, bounded numeric energy score and explicit residential designation. Missing/unparseable/conflicting fields stay absent.
11. **Asbestos fields:** reference/address, issue/printed expiry, explicit conclusion/safe flag, material count, structured action lines and PRIVATE_UNIT/COMMON_PARTS/COMMONLY_USED_PARTS/UNSPECIFIED scope.
12. **Electrical fields:** inspection body/reference, installation address/box, date/type, conforming flag/conclusion, structured infringements/follow-up. No diagram interpretation or cost estimates.
13. **Soil fields:** reference/date, cadastral division/section/parcel numbers, each explicit CaPaKey, GIR wording/flag, explicit risk-ground wording, labeled quality/advice and investigation references. No-GIR is never interpreted as clean soil; incomplete parcel coverage is explicit.
14. **Evidence/citations:** DOCUMENTED/DOCUMENT, source UUID, one-based page, half-open normalized-page offsets, confidence and adapter version. Typed EPC-label vocabulary; PostgreSQL guard rejects extractor promotion to OFFICIAL or missing document/page/parser provenance. No silent authority promotion.
15. **Requirements:** first-class per-evaluation results for EPC, asbestos private/common/common-used variants, electrical and soil. Applicability, presence and validity are separate, with reasons, document/evidence IDs, missing parcels, date and full rule metadata. Presence does not authenticate validity/signatures.
16. **Rule architecture:** explicit typed RuleContext, DocumentInput, Fact, RuleResult/RuleFinding; immutable normalized evaluation inputs/hash, catalog metadata and explicit date. No arbitrary expression language, plugin system, rules in API handlers or LLM generation. Europe/Brussels default date is supplied at service boundary.
17. **Exact codes/versions:** all 1.0.0: FL_EPC_REQUIRED, FL_EPC_RENOVATION, FL_ASBESTOS_REQUIRED, FL_ASBESTOS_COMMON_PARTS, FL_ASBESTOS_COMMONLY_USED, FL_ASBESTOS_VALIDITY, BE_ELECTRICAL_REQUIRED, BE_ELECTRICAL_NEGATIVE_SALE, FL_SOIL_REQUIRED, FL_SOIL_PARCEL_COVERAGE, FL_SOIL_RISK_GROUND, DOCUMENT_PROPERTY_ASSOCIATION. Last is a product safeguard, not a regulatory duty.
18. **Official authorities:** VEKA/Vlaanderen for EPC/renovation; OVAM for asbestos, validity, common-part timing and soil; FOD Economie/AREI for electrical. Each code's official source/review/limitations is recorded in the linked review and persisted output. No SEO/blog authority or private API was used.
19. **Effective dates:** asbestos transfer 2022-11-23, common-used 2025-05-01, VME common parts 2027-01-01. Other reviewed current-version coverage starts 2026-11-12; that is an implementation coverage bound, not the law's original commencement date. End dates are supported/inclusive; no repeal is invented. No retroactive six-year amendment claim.
20. **Findings:** conditional E/F renovation attention, printed asbestos expiry, non-conforming electrical sale/context follow-up, missing required evidence/soil parcel coverage, risk-ground review and document-identity review. Missing legally relevant dates prevent absolute deadlines. No overall score, purchase advice, sale prohibition or legal approval. Changed inputs resolve previous managed findings; unchanged inputs do not duplicate them; historical provenance remains until scoped deletion.
21. **Security/privacy:** READY/owner enforcement; bounded isolated parsing; minimal child environment; private derived artifacts and durable partial-write cleanup; no text logs; source-scoped export/deletion; additive DB provenance/source consistency controls. Focused notice/ROPA/matrix/DPIA updates, no new external document processor or training purpose. Existing production safety/hosting/legal launch gates remain.
22. **Tests added:** generated synthetic PDF builder; parser/OCR/bounds/classification/fields; API/manual/ownership; address/box/parcel isolation; rule applicability, effective ranges, dates/exceptions/expiry; idempotence/supersession/reassociation; exports, physical deletion and storage retry; DB authority and schema rollback guard.
