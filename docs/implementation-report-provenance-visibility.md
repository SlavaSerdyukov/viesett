# Viesett hotfix — human sources and internal provenance

2026-11-19. Small UX/API-projection fix on the existing 0.6.0 repository, no new milestone. Entry: `main` at `7bf0e30586f503d581750c73394611bd5a2230e7`, already containing uncommitted source/notary and demo-search/deletion work. The entry diff and hashes were saved before edits; existing work was preserved. This supersedes the technical-disclosure UI described in the [November 15 source/notary report](implementation-report-source-notary-fix.md), while retaining its human destinations, semantic deduplication, evidence/guidance groups, source appendix and separate print routes.

1. **Where provenance is stored.** Existing `EvidenceItem` rows retain `provider`, `fact_identifier`, `source_uri`, `source_retrieved_at`, `source_version`, `source_locator`, `authority` and lifecycle/history fields. The original owner-scoped citation DTO still contains `uri`, `technical_uri`, provider, identifier and retrieval metadata; private exports retain the existing provenance/history. No field was deleted, rewritten or reclassified. There is no migration or persistence change. The only additive response field is `EvidenceResponse.key`, projected directly from the already stored fact key, so the UI can distinguish explicit registry references from readable facts without parsing URLs or matching display labels.

2. **Where it was visible.** Shared `Citations` previously inserted a nested “Technical source” disclosure for non-document sources on normal Findings, Questions, Evidence and co-ownership/Overview presentations. Its body printed raw URI/fact identifier/retrieval information. The prior full print CSS hid those details but they remained in the page DOM; the concise notary page already used compact citations, yet its identity block printed address/unit registry numbers. Evidence also displayed provider object numbers and machine URI facts as ordinary values.

3. **Normal UI after the fix.** Shared citations now render only human labels, approved official destinations and private document-page links, with the existing semantic deduplication and Evidence / Rule / guidance grouping. Overview, Findings, Questions, Documents, Co-ownership, notary and full print have no provenance disclosure or raw API URI HTML. The reviewed exact URL catalog is unchanged; no arbitrary HTTPS value is promoted into a link. The human source may occur in each relevant matter; it remains deduplicated within that group and the appendix. Regulatory rule/check details remain distinct from technical provider provenance.

4. **Evidence advanced details.** Only `pages/Evidence.tsx` mounts `EvidenceSourceDetails`. Its native “Source details” disclosure starts closed and is keyboard-operable. Readable facts retain value, authority grouping, human source and date. Known provider object-number facts are presented as registry references; their object number appears only after disclosure. The explicit allowlist uses OFFICIAL authority plus exact fact keys for address/building/unit/parcel/heritage record references and municipality code. Heritage machine type URIs and matching internals are not printed, even after opening. Expanded details render only known human provider names, supplied retrieval dates and permitted object/code values. Raw fact identifiers, source URIs, arbitrary metadata, JSON, storage keys, filesystem paths, unrelated database IDs and credentials are never rendered. Versions/locators remain in the existing internal data/export rather than requiring a new metadata framework. Unknown provider names are not echoed; empty disclosures are omitted. Print media hides these details even if a user directly prints the Evidence screen after opening them.

5. **Raw API URI preservation.** Exact API/identifier URIs remain stored and serialized under the existing owner-only contracts. This change controls presentation, not what an authorized developer can inspect in network data or a private export. The strengthened DB/API regression compares provider, fact identifier, exact URI, retrieval timestamp, source version, authority and locator before/after dossier projection. The normal frontend never reads `technical_uri`/`uri` into visible text, links or technical details; presentation grouping still retains every original reference in memory/data.

6. **Raw API URI clickability.** No application source-citation API URI remains clickable, including on Evidence after disclosure. External source anchors still require exact membership in the existing reviewed human-destination catalog. Uploaded PDFs still use Viesett's authenticated private document/page viewer; its Blob/download behavior is unchanged. These statements concern application-generated source links, not arbitrary text/content inside an uploaded PDF or a user's private exported data.

7. **Notary handoff.** The dedicated concise route and content selectors are unchanged. Its header now describes the unit as matched/not confirmed, retaining any official box and legally useful parcel identifiers without printing address/unit registry object numbers. Important current matters, concise gaps/conditions, co-ownership/current funds/works, exact €6,000 estimate/inputs/assumptions, undetermined legal payment responsibility, NOTARY-only questions, readable appendix and disclaimer remain. No technical disclosure, endpoint, raw provider URI or internal provenance identifier is added. The synthetic scenario remains **3 A4 pages, 331,248 bytes**, 80% coverage at the unchanged 2026-11-12 demo evaluation date.

8. **Full dossier.** The separate full route retains all current findings, detailed requirements, co-ownership component information, calculations/assumptions and every question group. Its appendix remains grouped into public sources, uploaded documents and official guidance, with sorted deduplicated page references and credits. It has no technical appendix or raw-URI DOM; its existing details-opening logic explicitly excludes the new Evidence-only disclosure as a precaution. Native print help/header-footer limitations and source wrapping remain. The synthetic full example is **12 pages, 528,438 bytes**. All 15 pages of both final examples were rasterized with CoreGraphics and visually inspected; automated PDF text checks reject raw API URLs, technical/source-detail labels and print-help text. These are Chromium synthetic samples, not a real-document corpus or physical-printer certification.
